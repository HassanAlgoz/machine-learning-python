ضبط عتبة القرار (Post-tuning the Decision Threshold)

ربط الاحتمال بالقرار والمخاطر

التصنيف: توقّع الاحتمال مقابل اتخاذ القرار

تشبيه: الطقس: السؤال الأول “ما احتمال المطر غداً؟” — إجابة إحصائية (احتمال). السؤال الثاني “هل آخذ مظلتي؟” — قرار يعتمد على الاحتمال وعلى تكلفة الخطأ: تفويت المطر قد يكلف أكثر من حمل مظلة دون حاجة. عتبة القرار هي النقطة التي نقرر عندها “نعم” أو “لا” بناءً على الاحتمال (أو دالة القرار).

بلغة بسيطة: النموذج ينتج احتمالات (مثلاً عبر predict_proba) أو درجات (عبر decision_function). الـ predict الافتراضي يستخدم عتبة 0.5 للاحتمال أو 0 للدرجة. هذه العتبة قد لا تكون مناسبة عندما تكلفة “تفويت موجب” تختلف عن تكلفة “إيجابية كاذبة” — نضبط العتبة بعد تدريب النموذج لتعظيم مقياس مفيد أو تقليل تكلفة متوقعة.

تقني: في scikit-learn، التوقعات الافتراضية للمصنف الثنائي: موجب عندما \(P(y=1|X) > 0.5\) (من predict_proba) أو عندما decision_function > 0. راجع Tuning the decision threshold for class prediction.

ضبط العتبة بعد التدريب (Post-tuning)

مثال عملي: تطبيقنا لا تتسامح مع فوات اكتشاف مريض! نريد من النموذج أن يكون “موسوساً” أكثر ويقلل الثقة المطلوبة لاتخاذ قرار “مريض”. كيف نفعل ذلك؟

from sklearn.model_selection import train_test_split
from sklearn.ensemble import RandomForestClassifier
from sklearn.metrics import classification_report
from sklearn.model_selection import TunedThresholdClassifierCV

# 1. الموديل العادي (عتبة 0.5)
base_model = RandomForestClassifier(random_state=42)
base_model.fit(X_train, y_train)
print("Before Tuning (Default Threshold 0.5):")
print(classification_report(y_test, base_model.predict(X_test)))

# 2. ضبط العتبة لزيادة "الاستدعاء" (Recall)
# نطلب منه اختيار نقطة القطع التي تعظم recall عبر تحقق متقاطع داخلي
tuned_model = TunedThresholdClassifierCV(
    base_model, 
    scoring="recall", 
    cv=5
)
tuned_model.fit(X_train, y_train)

# 3. لنرى النتائج والعتبة التي اختارها
print(f"\nOptimal Threshold Found: {tuned_model.best_threshold_:.3f}")
print("After Tuning (Optimized for Recall):")
print(classification_report(y_test, tuned_model.predict(X_test)))

كيف تعمل هذه الآلية؟ النموذج ينتج لكل شخص احتمالية المرض (مثلاً 60% أو 30%). العتبة الافتراضية تقول “إذا تجاوز 50% فهو مريض”. ولكننا باستخدام TunedThresholdClassifierCV قمنا باختبار عتبات متعددة داخلياً، واكتشفنا أنه يمكننا زيادة الـ Recall (عدم تفويت مرضى) بخفض العتبة مثلاً إلى 30%. نحن لا نعيد التدريب من الصفر، بل نعيد تفسير الاحتمالات فحسب!

تحذير: لا تضبط العتبة وتصممها بناءً على بيانات التدريب المباشرة للنموذج حتى لا تنخدع بالأداء (Overfitting). استخدم إما تحققاً متقاطعاً داخلياً (كما فعلنا عبر cv=5) أو قم بضبطه على جزء منفصل تماماً من البيانات.

التعلم حساس التكلفة (Cost-sensitive learning)

فكرة: عندما نستطيع تحديد تكلفة كل نوع خطأ (TP, FP, FN, TN)، نختار العتبة التي تقلل التكلفة المتوقعة بدلاً من مجرد تعظيم accuracy أو F1. هذا يربط مقاييس النموذج بمقاييس العمل والمخاطر.

مورد: Post-tuning the decision threshold for cost-sensitive learning — يوضح ضبط العتبة وفق تكلفة وكيفية تجنب استخدام نفس البيانات للتدريب وضبط العتبة.

أمثلة عملية

  • كشف مرض: تكلفة FN عالية → نفضّل recall → عتبة منخفضة (نصنّف “موجب” حتى باحتمال أقل من 0.5).
  • تصفية بريد مزعج: تكلفة FP عالية (تفويت بريد مهم) → نفضّل precision → عتبة أعلى لتصنيف “مزعج”.

راجع أيضاً Post-hoc tuning the cut-off point of decision function.

خلاصة

المفهوم الاستخدام
عتبة افتراضية 0.5 مناسبة عندما تكلفتا الخطأ متقاربتان
TunedThresholdClassifierCV ضبط العتبة لتعظيم مقياس (recall, F1, مخصص) أو تقليل تكلفة
Cost-sensitive ربط التكلفة بكل نوع خطأ واختيار العتبة الأمثل
عدم استخدام نفس البيانات ضبط العتبة على تحقق (CV أو مجموعة تحقق) وليس على بيانات التدريب
