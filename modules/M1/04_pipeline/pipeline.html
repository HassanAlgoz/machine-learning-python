خط معالجة البيانات (Pipeline)

نتعلم في هذا الدرس:

  • الانتقال من النموذج إلى خط المعالجة (Pipeline) ومكوناته:
    1. المُقدّر (Estimator)
    2. المحوّل (Transformer)
    3. المتنبئ (Predictor)
  • التعامل مع الميزات العددية والوصفية:
    • تعويض القيم المفقودة
    • توحيد القياس للميزات العددية
    • ترميز الميزات الوصفية ## ما هو خط المعالجة (Pipeline)؟

هو الخط أو المسار السابق لدخول البيانات إلى خوارزمية التعلم. وذلك ليتم ضبط النموذج مع جميع المعالجات القبليَّة له جُملَةً واحدة؛ فالتغيير فيها أو في عوامل النموذج، كلاهُما يؤثر في نتيجة التنبؤ.

في مكتبة sklearn تم تسمية الوِحدة والقِطعة الواحدة في مسار المعالجة باسم المقدِّر (Estimator)، وهي إما:

  1. محوِّل (Transformer) وهي خطوات المعالجة التي تحصي من البيانات ثم تحولها.
  2. متنبئ (Predictor) وهي النموذج المتعلم من بيانات التدريب، القادر على التنبؤ.

لنفصّل الأمر:

1. المُقدّر (Estimator)

يتيميَّز بالإجراء fit() الذي إنما يحسب مقادير من البيانات؛ ولا يغير البيانات نفسها.

وهذا الصنف مجرَّد (Abstract Class) ؛ إذْ لا وجود لمقدِّر غير محول ولا متنبئ. بل لابد أن يكون أحدهما.

estimator = estimator.fit(data, targets)

أو

estimator = estimator.fit(data)

2. المحوّل (Transformer)

يضيف إلى التقدير، الإجراء transform() الذي يغير البيانات بناءً على المقادير التي تم حسابها من بيانات التدريب.

وإليك أمثلة للمحولات وعمل كلا الإجرائين فيه:

المحول التقدير: fit() التحويل: transform()
SimpleImputer يحسب الوسيط (أو القيمة المحددة حسب الاستراتيجية) لبيانات التدريب. يملأ القيم المفقودة في البيانات باستخدام القيمة المحسوبة.
StandardScaler يحسب المتوسط الحسابي والانحراف المعياري لبيانات التدريب. يطبق التحويل لتوحيد قياس البيانات.
OneHotEncoder يحدد الصفات الفريدة ويخصص ترميزاً أحاديًّا لكل منها. يطبق الترميزات على العينات ليحولها إلى أعمدة أحادية.
OrdinalEncoder يحدد الصفات الفريدة ويخصص لها ترتيباً عدديًا. يطبق الترميز ويحول الصفات إلى قيم عددية مرتبة.

يُستخدم لتعديل البيانات بطريقة تعليم خاضع للإشراف أو غير خاضع للإشراف (على سبيل المثال: إضافة أعمدة، أو تغييرها، أو إزالتها، ولكن ليس إضافة أو إزالة الصفوف). وينفذ كما يلي:

new_data = transformer.transform(data)

عندما يمكن تنفيذ عمليتي الملاءمة والتحويل معاً بكفاءة أعلى بكثير مما لو تم تنفيذهما بشكل منفصل، يتم تنفيذ: fit_transform()

new_data = transformer.fit_transform(data)

3. المتنبئ (Predictor)

مثل النماذج: LinearRegression, SGDRegressor, KNeighborsClassifier

فأما إجراءاته فهي:

  1. التقدير: fit(X) وهي ملاءمة النموذج للبيانات وفق خوارزمية التعلم الآلي المحددة. وهنا يحصل التعليم / التدريب.

  2. التنبؤ: predict(new_X) تطبّق النموذج على الحالات الجديدة فقط. prediction = predictor.predict(data) كما تضيف خوارزميات التصنيف احتماليَّة الصنف قبل الجزم، بإحدى الطريقتين:

  3. predict_proba(new_X) تعيد احتمالية الصنف لكل حالة.

  4. decision_function(new_X) تعيد قيمة تقريبية لاحتمال الصنف.

التقييم

يمكن قياس جودة الملاءمة أو احتمالية البيانات التي لم يسبق له رؤيتها في التدريب، كما يلي (كلما كانت القيمة أعلى، كان ذلك أفضل): score()

score = model.score(data)

خلاصة المقدرات

العنصر الإجراء الغرض
المُقدِّر (Estimator) fit() لملاءمة المعاملات من البيانات.
المُحوِّل (Transformer) transform() لتطبيق المعاملات التي تم حسابها أو تعلمها على البيانات.
المُتنبِّئ (Predictor) predict() لاستخدام المعاملات التي تم تعلمها للتنبؤ.
المُتنبِّئ (Predictor) score() لتقييم جودة الملاءمة (الأعلى أفضل).

المصدر: توثيق scikit-learn الرسمي لتصميم الواجهة البرمجية.

أهمية خط المعالجة في التعلم الآلي

أولها: الإجمال (عكس التفصيل): فبدلاً من كتابة كود طويل لكل خطوة كهذا:

X_train = step_1.fit_transform(X_train)
X_train = step_2.fit_transform(X_train)
X_train = step_3.fit_transform(X_train)
model.fit(X_train, y_train)

.. المسار يدمج الخطوات في كائن واحد، على النحو التالي:

model = Pipeline(
    steps=[
        ('Imputation', step_1),
        ('Encoding', step_2),
        ('Scaling', step_3),
    ]
)

.. فيكفي استدعاء fit() مرة واحدة على بياناتك لملاءمة سلسلة المقدرات جملةً واحدة:

model.fit(X_train, y_train)

وكذلك عند التنبؤ، لا حاجة لمعرفة تفاصيل التحويلات ثم كتابتها واحدة واحدة، بل هي محفوظة كقطعة متكاملة:

model.predict(X_new)

أما الفائدة الثانية والثالثة، فتتضحان ندخل في موضوع التقييم والتقويم، ونذكرهما هنا من غير تعقيب:

الثانية: تابعٌ للأوَّل، وهو الأمان (Safety)، فخط المعالجة يساعد على تجنب تسرب إحصاءات بيانات الاختبار إلى النموذج المدرب في التحقق المتقاطع (cross-validation)، بضمان استخدام نفس العينات لتدريب المحوّلات والمتنبئات كليهما.

الثالثة: ضبط المسار ككل: يمكنك البحث عن معلمات جميع المُقدّرات في المسار دفعة واحدة. (يُشرح لاحقاً. انظر: ضبط المعلمات الفوقية بالبحث الشبكي (Hyperparameter tuning by grid-search)).

1. تحميل مجموعة البيانات

نحتاج إلى تعريف البيانات والهدف (target). هنا نبني نموذج انحدار (regression model). from sklearn.datasets import fetch_openml

ames_housing = fetch_openml(name=“house_prices”, as_frame=True) data = ames_housing.data target = ames_housing.target نستعرض الصفوف الأولى من إطار البيانات (dataframe). data.head() ## 2. أخذ مجموعة فرعية من الميزات من أجل البساطة، يمكننا اختيار بعض الميزات (features) والاكتفاء بهذه المجموعة الفرعية من البيانات: numeric_features = [“LotArea”, “FullBath”, “HalfBath”] categorical_features = [“Neighborhood”, “HouseStyle”] data = data[numeric_features + categorical_features] ## 3. تعريف خطوات المعالجة المسبقة #### 3.1 الميزات العددية from sklearn.pipeline import Pipeline from sklearn.impute import SimpleImputer from sklearn.preprocessing import StandardScaler

numeric_transformer = Pipeline( steps=[ (“imputer”, SimpleImputer(strategy=“median”)), ( “scaler”, StandardScaler(), ), ] ) #### 3.2 الميزات الوصفية from sklearn.preprocessing import OneHotEncoder

categorical_transformer = OneHotEncoder(handle_unknown=“ignore”) ## 4. ربط التحويلات بالميزات (والهدف)

ثلاث نقاط يجب تذكرها:

  1. محوّل الأعمدة (ColumnTransformer) رابط يُستخدم لاختيار الميزات التي تُطبَّق عليها التحويلات المحددة.
  2. اتحاد الميزات (FeatureUnion) رابط يربط مخرجات المحوّلات في فضاء ميزات مركّب (composite feature space).
  3. أخيراً، لتحويل الهدف (target) (مثلاً تحويل لوغاريتمي لـ y) استخدم متنبئ الهدف المحوّل (TransformedTargetRegressor) رابط. from sklearn.compose import ColumnTransformer

preprocessor = ColumnTransformer( transformers=[ (“num”, numeric_transformer, numeric_features), (“cat”, categorical_transformer, categorical_features), ] ) ## 5. تعريف المسار تعريف نموذج الانحدار (regression model).

أحياناً نسمّي المسار بالكامل النموذج (model). لذلك نسمي المتنبئ (predictor) بهذا الاسم. from sklearn.linear_model import SGDRegressor

predictor = SGDRegressor(loss=“squared_error”) ربط الخطوات بالمتنبئ (predictor). model = Pipeline( steps=[ (“preprocessor”, preprocessor), (“regressor”, predictor), ] ) model - لنجرِ الملاءمة (fit)! - لاحظ كيف يتغيّر لون الرسم بعد ملاءمة المُقدّر (estimator). model.fit(data, target) إضافة: يمكننا بدلاً من ذلك استخدام واجهة الدوال (functional API): make_column_transformer و make_pipeline، ولا تتطلبان ولا تسمحان بتسمية المُقدّرات يدوياً؛ بل تُعيَّن أسماؤها تلقائياً بأحرف صغيرة من أنواعها.

from sklearn.compose import make_column_transformer
from sklearn.pipeline import make_pipeline

numeric_transformer = make_pipeline(
    SimpleImputer(strategy="median"), StandardScaler()
)
categorical_transformer = OneHotEncoder(handle_unknown="ignore")

preprocessor = make_column_transformer(
    (numeric_transformer, numeric_features),
    (categorical_transformer, categorical_features),
)
model = make_pipeline(preprocessor, SGDRegressor())
model.fit(data, target)

6. تقييم المسار

تقييم النموذج (Model Evaluation) يحتاج نقاشاً مستقلاً، لكن نعرضه هنا للاكتمال. from sklearn.model_selection import cross_validate

cv_results = cross_validate(model, data, target, cv=5) scores = cv_results[“test_score”] print( “The mean cross-validation accuracy is:” f”{scores.mean():.3f} ± {scores.std():.3f}” ) — دفتر مرتبط: مسار تعلم آلي تنبؤي مع أنواع بيانات مختلطة (Predictive machine learning pipeline with mixed data types).
